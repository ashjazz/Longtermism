# 契约：P0-A 模型供应商 Adapter

## 目的

本契约定义 P0-A 首个模型供应商 adapter 必须满足的行为。首个实现采用 OpenAI-compatible 形态，但框架核心只依赖通用模型供应商契约。

## 输入契约

一次模型请求必须包含：

- `model`：目标模型标识。
- `messages`：消息列表，至少包含一条用户或系统可解释消息。
- `tools`：可选工具声明。
- `structured_output`：可选结构化输出约束。
- `temperature`：可选生成随机性参数。
- `max_tokens`：可选输出预算。
- `reasoning_effort`：可选推理强度。
- `context`：调用方提供的取消和超时控制。

## 输出契约

一次非流式响应必须包含：

- `content`：最终文本内容，可为空但必须与 finish reason 一致。
- `model`：实际服务模型。
- `usage`：用量信息；供应商未返回时允许为零值，但必须可被 trace 标记。
- `finish_reason`：终止原因。
- `tool_calls`：结构化工具调用请求列表，可为空。

一次流式响应必须满足：

- 按顺序产生增量内容。
- 可表达增量工具调用。
- 结束时表达终止原因。
- 供应商返回用量时，最后阶段携带用量。
- 流中错误通过 chunk 错误字段暴露，然后关闭流。

## 错误契约

必须稳定区分：

- **可重试/可降级上游错误**：超时、取消、限流、5xx、连接失败。
- **不可重试调用方错误**：参数错误、认证失败、权限不足、资源不存在。
- **协议错误**：供应商响应格式不符合 adapter 预期。

可重试/可降级上游错误必须能被上层识别为 `ErrUpstream` 等价语义。不可重试调用方错误不得被包装成上游错误。

## 能力声明契约

adapter 必须能按模型返回能力声明，包括：

- 是否支持工具调用。
- 是否支持 strict 结构化输出。
- 是否支持流式输出。
- 是否支持流式工具调用。
- 是否支持推理强度参数。
- 是否支持 prompt caching。
- 是否支持视觉输入。

P0 可使用保守静态表或配置表，不要求网络探测。

## P0 测试契约

P0-A 默认测试必须覆盖：

- 正常非流式响应。
- 工具调用解析。
- 429、5xx、timeout 映射为上游错误。
- 400、401 不映射为上游错误。
- 流式增量顺序和最终用量。
- 调用方取消后尽快返回。
- 缺少必需输入时快速失败。

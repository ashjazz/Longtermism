# 契约：评估与可观测性

## 目的

本契约定义 P0-C 和 P0-D 的最低行为：每个 AI 能力都必须可追踪、可评估、可回归。

## Trace 契约

每条关键 AI trace 至少应能表达：

- `trace_id`：唯一追踪标识。
- `feature`：能力或功能名称。
- `model`：模型身份。
- `prompt_version`：提示词版本。
- `prompt_hash`：渲染提示词 hash。
- `input_tokens`、`output_tokens`、`reasoning_tokens`：用量。
- `ttft_ms`、`total_latency_ms`：延迟。
- `retrieval_summary`：检索摘要，若适用。
- `cost_ready_fields`：后续成本计算所需字段。
- `outcome_status`：成功、失败、降级或终止原因。

普通 trace 不得包含原始敏感内容。

## Dataset 契约

评估数据集必须支持：

- 加载多个样例。
- 每个样例拥有稳定 ID。
- 每个样例标注输入、期望结果或相关上下文。
- 每个样例可标注难度和类别。

## Metric 契约

评估指标必须支持：

- 稳定名称。
- 单样例评分。
- 评分范围清晰。
- 错误可诊断。

P0 首批指标应优先确定性指标，例如完全匹配、关键词覆盖、上下文命中。

## Report 契约

评估报告必须包含：

- 数据集版本。
- 样本数量。
- 指标均值。
- 回归指标列表。
- 运行状态。

## 门禁契约

默认评估冒烟必须：

- 不依赖真实外部模型。
- 输出稳定结果。
- 失败时能说明失败样例或失败指标。
- 可被本地命令和后续 CI 复用。

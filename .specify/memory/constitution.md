# 项目宪章：AshJazz AI Agent Framework

## 核心原则

### 一、评估先行

任何 AI 能力必须先定义可重复验证方式，再声明能力完成。完成标准至少包含测试、评估或回归证据、失败模式、降级路径、可观测性和文档。

### 二、核心抽象独立

AI 内核必须通过稳定抽象表达能力。模型供应商、向量数据库、可观测平台、缓存和评估平台都只能作为可替换后端接入，不得成为核心能力契约。

### 三、生产失效可见

每个关键路径必须能说明如何失败、如何被观察、如何降级，以及延迟、成本和可靠性之间的取舍。

### 四、轻量 Harness 优先

项目默认自建 lightweight Agent Harness。第三方框架只能作为 adapter 或应用层集成，除非通过决策记录证明其不会隐藏 prompt、token、tool 参数、cost、trace 和降级行为。

### 五、学习可沉淀

重要故障、权衡和修复必须沉淀到文档、决策记录或学习日志中，使项目同时服务于工程交付和成长复盘。

## 质量门禁

- 新功能必须遵循 TDD 或等价的失败用例先行流程。
- 默认验证不能强制依赖实时外部付费服务。
- 涉及密钥、用户输入、文件系统、外部调用或敏感数据时，必须显式考虑安全边界。
- 不允许通过主观观察单独宣布 AI 能力完成。

## 治理

- `AGENTS.md` 是项目专属开发规则入口。
- `准备清单.md` 是能力深度和面试目标的规格来源。
- `docs/ROADMAP.md` 是阶段推进顺序来源。
- `specs/*` 是 spec-kit 规格、计划与任务拆分来源。

在向量检索（ANN）中，**HNSW、IVF 和 PQ** 是三种最主流的底层算法架构。它们的核心思路不同：HNSW 靠“图”连结，IVF 靠“分类”聚集，PQ 靠“压缩”降维。

以下是这三个算法在各个维度的核心区别与详细对比。

------

## 一、 核心原理与机制

## 1. HNSW (Hierarchical Navigable Small World)

- **机制**：基于**多层图**结构。最底层包含所有向量，越往上层向量越稀疏。
- **检索思路**：从顶层稀疏图开始粗查，找到最近邻后跳入下一层继续精查（类似跳表 `Skip-List`），直到最底层找到精确结果。

## 2. IVF (Inverted File Index)

- **机制**：基于**聚类**（通常是 K-Means）的倒排索引。将向量空间划分为 $K$ 个聚类中心（桶）。
- **检索思路**：查询时，先计算目标向量属于哪几个聚类中心，然后只在这几个桶内部进行遍历检索，直接剪枝掉绝大多数不相关的向量。

## 3. PQ (Product Quantization)

- **机制**：基于**空间切分与量化**的压缩算法。将高维向量切分成多个低维子向量，对每个子向量空间进行聚类并编码。
- **检索思路**：将原始浮点数向量压缩为极短的字节编码。检索时通过**非对称距离计算（ADC）**，直接用查询向量与码本计算距离，查表得到近似结果。

## 二、 综合性能对比维度

| 对比维度         | HNSW (基于图)                                                | IVF (基于聚类)                                               | PQ (基于压缩)                                             |
| :--------------- | :----------------------------------------------------------- | :----------------------------------------------------------- | :-------------------------------------------------------- |
| **构建索引效率** | **极慢**。需要为每个点计算近邻并建边，计算复杂度高。         | **快**。只需运行 K-Means 聚类并分配标签。                    | **中等**。需要训练码本并对所有向量进行量化编码。          |
| **更新索引效率** | **较好（增量强）**。支持动态插入新点并更新局部邻居边。       | **差（需重构）**。新数据多会导致聚类失衡，需重新聚类。       | **极差**。增量数据过多会导致码本失真，需要重新训练。      |
| **检索效率**     | **极快**。图导航速度极快，响应时间通常在毫秒级。             | **快**。取决于查找的桶数，桶少则极快，桶多则变慢。           | **中等**。由于主要是查表和位运算，单核吞吐量高但精度低。  |
| **内存占用**     | **极高**。需要常驻内存，除原始向量外还要存大量的图结构边信息。 | **低**。仅多存了聚类中心和倒排链表表头，主要是原始向量体积。 | **极低**。内存占用可降低至原始向量的 $1/10$ 甚至 $1/16$。 |
| **检索精度**     | **极高**。召回率（Recall）轻易可达 95% ~ 99% 以上。          | **中等**。容易漏掉边界处的近邻，召回率通常在 80% ~ 95%。     | **低**。因为存在量化误差，通常不单独用于高精度检索。      |

## 三、 关键参数解析

## 1. HNSW 关键参数

- `M`：每个节点在构造图时最大连接的邻居边数（常用 16~64）。**M 越大，高维检索精度越高，但内存占用和建索引时间翻倍。**
- `efConstruction`：建索引时探索的邻居深度（常用 200~500）。**越大建图越慢，但图质量和精度越高。**
- `efSearch`：检索时探索的邻居深度。**在检索时动态调节，越大检索越慢但精度越高。**

## 2. IVF 关键参数

- `nlist`：聚类中心（桶）的数量。**nlist 越大，建索引越慢，每个桶内向量越少，检索越快。**
- `nprobe`：检索时查询的桶的数量（$nprobe \le nlist$）。**在检索时调节，nprobe 越大，查的桶越多，召回率越高，但速度变慢。**

## 3. PQ 关键参数

- `M`（注意与 HNSW 的 M 不同）：将原始向量切分成多少个子向量（如 512 维切成 M=64 个 8 维子向量）。**M 越大，压缩率越低，内存占用变大，但精度越高。**
- `nbits`：每个子向量聚类中心的比特数（通常设为 8，代表 256 个聚类中心，刚好用 1 字节存储）。

## 四、 实际生产中的混合变体

在实际的向量数据库（如 Milvus, Faiss, Pinecone）中，为了结合各自的优点，通常会将它们**组合使用**：

1. **IVF_PQ (最经典组合)**：
   - **原理**：先用 IVF 把空间分成大桶，再用 PQ 把桶里的向量压缩。
   - **效果**：完美解决了 IVF 内存占用大和 PQ 检索慢的问题，是大规模海量数据（亿级以上）的首选方案。
2. **HNSW_PQ / SCaNN**：
   - **原理**：用 HNSW 的多层图替代 IVF 的聚类中心导航，底层向量使用 PQ 或其他量化手段压缩。
   - **效果**：在保证极高检索速度的同时，大幅降低了 HNSW 的内存占用。
